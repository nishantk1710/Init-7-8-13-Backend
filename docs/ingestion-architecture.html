Before this runs live

Three things the diagram assumes that aren't true yet.

⚠  Storage grant missing

The App Service identity holds Reader on the storage account. The CSV receiver and the delta writer both need Storage Blob Data Contributor to land anything.

⚠  One extract at a time

Chunks carry no request id or sequence number. The "append to the currently open table" logic only holds if extracts are fired serially, never in parallel.

✓  Watermark handoff

A CSV load writes no watermark by itself. The loader must seed ingest_watermark from the max date column in the landed file, or the next OData delta has nothing to start from.
